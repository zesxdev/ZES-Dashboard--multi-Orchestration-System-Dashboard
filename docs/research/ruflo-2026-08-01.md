## Recommendation: cherry-pick, do NOT install wholesale

Full `npx ruflo init` is heavy (Rust crates, sql.js, HNSW, daemon, MCP server),
alpha-grade (518 open issues), and writes its own `.claude/` + skills that
would collide with ZES's hand-rolled trinity, Memory Hub, and runsv stack.
On this phone (2.4 GB RAM free, Node v26) it is feasible but not worth the
operational surface.

### Adopt (high value / low effort)
1. **Memory vectors** — resolve ROADMAP item "Memory search with vector
   embeddings": embed facts (small local model or BitRouter embeddings),
   store vectors in SQLite, top-k ANN via FTS5 prefilter + cosine. Keep hub
   as source of truth.
2. **Memory consolidation** — automate `memory-health.sh` as a runsv timer
   (sweep expired, dedup by content hash, report).
3. **Loop discipline** — extend ZES-self-improvement with explicit
   receipt/benchmark steps (record what worked, cost, duration) into
   `~/.zes/learnings/`.
4. **One-off audit** — `npx ruflo metaharness score --path ~/Zes-System` for
   a free gap analysis of our harness (static, disposable).

### Skip
Federation/WireGuard mesh, swarm CLI, security publish pipelines, full plugin
catalog (35 plugins), RuVector Agentic DB (separate heavy dependency).
